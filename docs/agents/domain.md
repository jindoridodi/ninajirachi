# Domain Docs

This is a single-context repository.

Before exploring or changing the project:

- Read `GLOSSARY.md` at the repository root.
- Read relevant decisions under `docs/adr/` when that directory exists.
- Use glossary terms in issue titles, specs, tests, and implementation notes.
- If a proposed change conflicts with an ADR, surface the conflict before proceeding.

The domain glossary defines project language only; it does not contain implementation details or act as a specification. Create or update glossary entries when project terms become precise. Create ADRs only for hard-to-reverse, surprising decisions that resulted from a real trade-off.
